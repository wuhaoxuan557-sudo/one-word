# 给 Codex 的提示词

## 用法

1. 在 GitHub 新建一个空仓库（比如 `vocab`），把这个压缩包里的所有文件放到仓库根目录，然后提交。
2. 打开 Codex，连接这个仓库。`AGENTS.md` 会被 Codex 自动读取，不用另外粘贴。
3. 按顺序粘贴下面的提示词，**一次只贴一条**。每条做完后，先在电脑浏览器和手机上看一遍，确认没问题再贴下一条。
4. 如果你的 Codex 支持附图，贴提示词时把对应的截图（`design/screens/`）一起附上，效果更好。附不了也没关系，`design/html/` 才是权威来源，Codex 能直接读。

此外需要你手动做一件事：从 https://github.com/skywind3000/ECDICT 下载 `ecdict.csv`（在仓库根目录或 Releases 里，几十 MB），放到仓库里的 `data/` 目录，并把 `data/` 加进 `.gitignore`。

## 0. 先出计划，不写代码

```
通读 AGENTS.md、SPEC.md、design/html/ 下的全部文件。先不要写任何代码。

用中文回复我三件事：
1. M1 的实施计划：要建哪些文件、组件怎么拆分、数据怎么流动。
2. 你认为 SPEC.md 里不清楚、互相矛盾或者实现起来有风险的地方（逐条列出，并说明你建议怎么处理）。
3. 照设计稿还原时你预计最容易走样的地方。
```

看完它的回复，有意见就直接回复它修改计划；没意见再进行下一步。

## M1：词表脚本 + 认词流程

```
开始做 M1（见 SPEC.md 第 8 节）。范围：

- scripts/build_wordlist.py：按 SPEC 第 2 节实现，输入是 data/ecdict.csv。
- src/styles/tokens.css：按 SPEC 7.2 节定义所有变量，包括深色模式。
- 字体：按 SPEC 7.3 节，把 assets/fonts/ 引入项目。
- 认词 → 反馈 → 详情三个屏幕，视觉严格按 design/html/02-quiz.html、03-feedback-wrong.html、04-detail.html 还原，交互按 SPEC 3.2 和 7.5 节。
- 数据只放内存。用 ielts 词表随机抽 20 个词跑通流程即可，不需要调度。
- 发音按 SPEC 第 4 节实现。
- src/core/ 下的干扰项生成和 exchange 解析写成纯函数，并附 Vitest 测试。

完成后停下，告诉我：怎么运行脚本、怎么在本地打开、怎么在手机上（同一 Wi-Fi 下）访问开发服务器。
```

> **如果你想自己写 Python 脚本练手**，把上面第一条换成：
> "scripts/build_wordlist.py 由我自己写，你不要写。先手写一个 public/wordlists/sample.json（20 个词，字段格式按 SPEC 第 2 节），前端用它开发。"

## M2：持久化 + FSRS 调度

```
开始做 M2。范围：

- 用 Dexie 建 SPEC 第 6 节的三张表。
- 用 ts-fsrs 实现调度，评分映射按 SPEC 3.3 节，阈值读取 settings。
- 每日队列按 SPEC 3.1 节构建（先复习后新词、上限、按词频排序、多词表去重）。
- 首页按 design/html/01-home.html 还原，数字要显示真实数据。"约 N 分钟"的估算方法见 SPEC 7.5 节。
- 斩：按 SPEC 3.3 和 7.5 节实现，包括"已斩 · 撤销"提示条。
- 测试覆盖：评分映射（每个边界值都要测）、队列构建、斩以后不再出现、跨天时队列的行为。

完成后停下，说明你怎么验证"关掉页面再打开，进度还在"。
```

```
开始做 M3。范围：
```

## M4：PWA 离线 + 部署

```
开始做 M4。范围：

- 用 vite-plugin-pwa 实现离线：首次加载后断网也能完整使用，包括词表 JSON 和字体。
- 启动时调用 navigator.storage.persist()。
- 准备好 manifest 和图标。图标用黑底、白色"斩"字的方印，风格和 App 内的斩印一致，用 assets/fonts/zhan-seal.woff2 生成 PNG。
- 写 GitHub Actions workflow，push 到 main 后自动部署到 GitHub Pages（注意 Vite 的 base 路径要设置成仓库名）。
- 更新 README：部署步骤，以及在 iPhone Safari 上"添加到主屏幕"的步骤。

完成后停下，告诉我怎么验证离线是否真的生效。
```

## 常用的追加提示

**界面走样时：**
```
把 <屏幕名> 和 design/html/<文件名>.html 逐项对比：间距、字号、字重、颜色、圆角、描边。列出所有不一致的地方，然后全部改掉。
```

**出 bug 时：**
```
复现步骤：<你做了什么>
期望结果：<应该发生什么>
实际结果：<实际发生了什么>
先找出根本原因并解释给我听，再修。修完后补一个能抓住这个 bug 的测试。
```
